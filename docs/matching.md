# Механика подбора и категоризация

## 1. Категория кандидата

Кандидат попадает в **категорию** = связка `(стек, грейд, роль)` + достижения ФСП.

```js
categorizeCandidate(candidate, achievements) → {
  category: { stack: [...], grade: 'junior|middle|senior|lead', role, work_format, city },
  verified: <bool — есть подтверждённые достижения>,
  achievementsCount: <int>,
  gradeBoosted: <bool — грейд поднят по ФСП>,
}
```

### Подтверждённый грейд

- Приоритет — `verified_grade` (установлен после успешного теста).
- Если его нет, используется заявленный (`grade`).
- Если у кандидата ≥2 достижений ФСП и заявленный грейд = `middle`, он
  автоматически повышается до `senior`.
- Если ≥1 достижение и `junior` → повышается до `middle`.

## 2. Скоринг кандидата под вакансию

`scoreCandidate(candidateCategory, vacancy)` возвращает число 0..100 + breakdown:

| Компонент | Максимум | Логика |
| --- | --- | --- |
| Стек | 60 | `(пересечение / размер стека вакансии) * 60` |
| Грейд | 25 | Полное совпадение — 25, разница в 1 уровень — 12 |
| Роль | 10 | Точное совпадение — 10 |
| Достижения ФСП | 5 | `verified` — 5 |

Сортировка: по `score` desc, при равенстве — по `achievementsCount` desc.

## 3. Ранжирование внутри категории (для подборки и поиска)

`rankInCategory(category, bestTestPercent)`:

| Сигнал | Максимум |
| --- | --- |
| Лучший результат теста (`max(percent)` по `test_attempts`) | 70 |
| Достижения ФСП (`achievementsCount * 10`) | 30 |

Используется в `/api/candidates/search` (поиск по банку), чтобы показать
сильнейших в каждой категории.

## 4. Поиск по банку

`/api/candidates/search?role=...&grade=...&stack=...&work_format=...&city=...&fsp_only=...`

- Фильтрация выполняется **поверх** уже категоризированного списка — уточнение
  запроса не пересчитывает категории.
- Возвращает `{total, results: [{candidate, category, rank}]}`.
- Работодателю контакты (`email`, `telegram`, `phone`) маскируются до тех пор,
  пока кандидат не принял оффер или не откликнулся.

## 5. Подбор по вакансии

`/api/vacancies/:id/matches` — скоринг конкретной вакансии по всем категориям
кандидатов.

- В выдачу попадают кандидаты с `score > 0` (т. е. с ненулевым пересечением).
- Отсортированы по `score` desc и `achievementsCount` desc.
- Работодателю контакты по умолчанию скрыты; см. `server/visability.js`.

## 6. Объяснимость выдачи

Каждый результат содержит `breakdown: {stack, grade, role, fsp}` — разбивку баллов.
Это даёт работодателю возможность сразу увидеть, почему кандидат попал в подборку.

## 7. Концепция категорий (пример)

```
{stack: [python, go], grade: middle, role: backend} → бэкенд-разработчики с опытом
{stack: [js, react, ts], grade: junior, role: frontend} → фронтенд-разработчики до года
{stack: [python, ml], grade: senior, role: ml} → сильные ML-инженеры
```

Категории **объективно подтверждаемы** (тест + достижения ФСП), а не
самоописательны. Это центральное отличие платформы от универсальных job-бордов.
