# Приватность, согласия и защита данных (152-ФЗ)

## 1. Принципы

- Обработка персональных данных осуществляется только при наличии **согласия**
  пользователя (кандидата) на обработку и публикацию данных профиля.
- Кандидат управляет приватностью: решает, какие поля видны работодателю
  (настройки приватности).
- Работодатель **не видит контактные данные кандидата** до момента, когда кандидат
  принял приглашение или откликнулся сам (правило §2.2.2 ТЗ).
- Пароли и токены хранятся только в защищрованном виде (bcrypt / JWT с отзывом).
- Аудит-лог действий пользователей (`audit_log`) ведётся в обязательном порядке.
- В будущем ФСП ID будет на базе Keycloak — модуль auth изолирован для миграции.

## 2. Видимость контактов (правила §2.2 ТЗ)

Работодатель видит контакты кандидата (`email`, `telegram`, `phone`) **только если**:

1. Кандидат явно выставил `privacy_show_contacts = 1` (явное согласие на показ всем);
2. Кандидат **принял** оффер (`offers.status = 'accepted'`) от этой компании;
3. Кандидат **сам откликнулся** на вакансию этой компании (`applications` существует).

Реализация: `server/visability.js` (функция `canViewContacts`).
Применяется в:
- `/api/candidates/search` (поиск по банку);
- `/api/candidates` (общий список);
- `/api/offers/:id/contact` (явный endpoint раскрытия контактов).

## 3. Настройки приватности кандидата

| Поле | Значение по умолчанию | Описание |
| --- | --- | --- |
| `privacy_publish` | 1 | Публиковать профиль для работодателей (выкл = инкогнито) |
| `privacy_show_contacts` | 0 | Показывать контакты всем работодателям без условий |
| `privacy_show_achievements` | 1 | Показывать достижения ФСП в публичном профиле |
| `privacy_show_in_search` | 1 | Включать кандидата в подборки |

API: `PUT /api/me/privacy`.

## 4. Аутентификация и авторизация

- `POST /api/auth/register` — создание пользователя (`role: 'candidate' | 'employer'`).
- `POST /api/auth/verify-email` — подтверждение email по коду (в MVP код
  логируется в консоль сервера и в `data/email-outbox.log`).
- `POST /api/auth/login` → JWT (TTL 7 дней, отзывается на `/api/auth/logout`).
- Пароль: bcryptjs, 10 раундов; минимум 6 символов.
- `auth.requireAuth` + `auth.requireRole(role)` — ролевые guards на всех
  приватных маршрутах.

## 5. Защита от злоупотреблений

- Rate-limit на создание вакансий — `moderation.canPostVacancy`: 5/час на пользователя.
- Жалобы на вакансии: `POST /api/vacancies/:id/report`. При ≥3 жалобах вакансия
  переводится в `moderation_status = 'review'` и не показывается в публичной выдаче.
- `admin@local` решает по жалобам: `POST /api/admin/moderate/:vacancyId` →
  `ok | review | hidden`.
- Все мутации пишутся в `audit_log`.

- [x] Документированные настройки приватности в кабинете кандидата.
- [x] Регистрация по email с подтверждением (код).

## 7. Миграция на Keycloak

`server/auth.js` инкапсулирует всю работу с пользователями. Для перевода на
Keycloak:

1. Заменить `bcryptjs + jsonwebtoken` на OIDC-client + Keycloak confidential client.
2. `auth.requireAuth` оставить сигнатуру, переписать на верификацию access_token.
3. Хранить `keycloak_sub` в `users.id_external` (миграция в `server/db.js`).
4. `auth.me(userId)` → Keycloak `/userinfo`.
