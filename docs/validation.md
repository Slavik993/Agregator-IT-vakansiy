# Процедура валидации решения

## 1. Цель

Оценить качество ключевых механик MVP:

1. **Механика тестирования**: согласованность (стабильность грейда при повторном
   прохождении), дискриминативность (разделение слабых и сильных кандидатов),
   устойчивость к распространению заданий.
2. **Механика подбора**: доля релевантных кандидатов в топе выдачи на тестовом наборе
   пар «вакансия – кандидат».

## 2. Тестовые данные (синтетические)

Поскольку готовых датасетов нет, команда строит собственную процедуру валидации.

### 2.1 Кандидаты

Генерируются синтетические профили со следующими параметрами:

| Параметр | Значения |
| --- | --- |
| Специализация | backend, frontend, ml |
| Грейд (истинный) | junior, middle, senior |
| Стек | из справочника технологий соответствующей роли |
| Опыт | 0–8 лет |
| Достижения ФСП | 0–3 записи (или отсутствуют) |
| Результат теста | моделируется: истинный грейд → ожидаемый процент |

### 2.2 Вакансии

Набор описаний вакансий (5–10 штук) с фиксированной связкой «стек + грейд + роль».
Для каждой вакансии экспертно составляется эталонная разметка: какие кандидаты
релевантны (должны попасть в топ).

## 3. Метрики

### 3.1 Для тестирования

- **Согласованность (reliability)**: кандидат одного истинного грейда проходит тест
  N раз (N=5); результат не должен «скакать» более чем на один грейд.
  Метрика: доля попыток, где `result` соответствует истинному грейду ≥ 80%.
- **Дискриминативность (discrimination)**: распределение процентов для junior/middle/senior
  должно разделяться. Метрика: средний процент(junior) < средний процент(middle)
  < средний процент(senior).
- **Устойчивость к утечке**: при повторном прохождении с теми же выученными ответами
  на предыдущий набор, процент не должен гарантированно превышать порог (случайная
  выборка + параметрические задания).

### 3.2 Для подбора

- **Precision@k**: доля релевантных кандидатов в топ-5 выдачи для каждой вакансии.
- **MRR (Mean Reciprocal Rank)**: средний обратный ранг первого релевантного кандидата.
- **Coverage**: доля вакансий, для которых найдено хотя бы одно совпадение.

## 4. Скрипты валидации

В репозиторий добавлен скрипт `server/validate.js`, который:

1. Генерирует синтетических кандидатов (истинные грейды известны).
2. Прогоняет движок тестирования (генерация + оценка) для каждого кандидата.
3. Считает метрики согласованности и дискриминативности.
4. Формирует подборку для каждой тестовой вакансии и считает Precision@k / MRR.
5. Выводит отчёт в консоль и в `data/validation-report.json`.

Запуск:

```bash
npm run validate
```

## 5. Ожидаемые результаты (целевые значения)

| Метрика | Цель |
| --- | --- |
| Доля попыток с корректным грейдом | ≥ 80% |
| Монотонность среднего процента по грейдам | соблюдена |
| Precision@5 | ≥ 0.7 |
| MRR | ≥ 0.75 |
| Coverage | = 100% |

## 6. Ограничения

- Синтетические данные не заменяют реальную разметку; после хакатона планируется
  валидация на данных ФСП.
- Пороги теста (55%/85%) выбраны эмпирически и могут быть откалиброваны по результатам
  реальных прохождений.
