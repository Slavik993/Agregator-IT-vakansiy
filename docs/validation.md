# Процедура валидации решения

## 1. Цель

Подтвердить, что:

1. **Механика тестирования** стабильно подтверждает заявленный грейд и
   разделяет сильных/слабых кандидатов (дискриминативность).
2. **Механика подбора** выдаёт релевантных кандидатов в топе выдачи.
3. **Категоризация** корректно связывает стек, грейд и роль с подтверждёнными
   достижениями.

## 2. Запуск

```bash
npm run validate
```

Скрипт (`server/validate.js`):

1. Генерирует 60 синтетических кандидатов с известным «истинным» грейдом.
2. Прогоняет `generateTest + emulateAnswers + gradeAttempt` для каждого
   (в среднем 5 попыток на кандидата).
3. Считает метрики тестирования и подбора.
4. Сохраняет отчёт в `data/validation-report.json`.

## 3. Метрики тестирования

| Метрика | Описание | Цель |
| --- | --- | --- |
| `confirmedGradeShare` | Доля попыток с `result ∈ {passed, confident}` | ≥ 80% |
| `meanPercentByTrueGrade` | Средний процент по истинному грейду | возрастает с грейдом |
| `monotonic` | `junior < middle < senior` по среднему проценту | `true` |

## 4. Метрики подбора

| Метрика | Описание | Цель |
| --- | --- | --- |
| `precisionAt5` | Доля релевантных в топ-5 выдачи | ≥ 0.7 |
| `mrr` | Mean Reciprocal Rank первого релевантного | ≥ 0.75 |
| `coverage` | Доля вакансий, для которых есть хотя бы один релевантный кандидат | = 1 |

Релевантность (`isRelevant`): пересечение по стеку > 0 **и** разница по грейду ≤ 1.

## 5. Текущие результаты

После `npm run validate` на стандартных синтетических данных:

```text
Кандидатов: 60
Подтверждённый грейд: ~90%
Precision@5: ~0.8
MRR: ~0.8
Coverage: ~0.8
```

Отчёт сохраняется в `data/validation-report.json`. Конкретные значения зависят
от банка заданий и seed-данных; при изменении банка рекомендуется пересмотреть
пороги `PASS_THRESHOLD` / `CONFIDENT_THRESHOLD`.

## 6. Smoke-тест

```bash
npm run smoke
```

24 проверки end-to-end:

- регистрация кандидата и работодателя;
- вход и работа с JWT;
- заполнение профиля;
- прохождение теста;
- создание вакансии;
- получение подборки;
- оффер (с обязательной зарплатой);
- скрытие контактов до `accepted`;
- приватность;
- отклик (application);
- регулярные задания (assign → submit → review);
- жалоба на вакансию;
- PDF-профиль;
- ATS push;
- rate-limit на создание вакансий.
